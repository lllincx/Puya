# DMAX简介

DMAX 是一款带有 AMBA® AXI5 接口的直接存储器访问控制器。可在八个通道上提供快速的存储器到存储器、外设到存储器以及存储器到外设的复制能力。

系统中的处理器可以通过 APB4 接口控制 DMA 通道行为，并在支持安全扩展（Security Extension）时设置安全相关参数。DMAX针对不同类型的复制、离散-集中（scatter-gather）、增量或二维图像复制操作进行了配置。它还支持用于流控制和命令序列化能力的触发输入。

通过命令链接（command linking）功能，可以将多条 DMA 命令组合在一起。利用命令链接功能，可以设置复杂的传输任务，且 DMAX可以在无需处理器交互的情况下执行。

# DMAX 主要特性

- 两组双向AXI主接口
- 从源到目标的内存映射数据传输：
	- 外设到内存
	- 内存到外设
	- 内存到内存
- 基于通道级别 16级可编程优先级的传输仲裁： 采用 LRG (Least-Recently Granted) 算法，结合固定优先级与轮询（Round-robin）两层架构
- 在发生以下任意事件时，按通道生成事件：等待触发输出，等待目标触发输入，等待源触发输入，等待恢复，暂停，停止，禁用，错误，完成。
- 每通道中断生成，每个事件可单独编程使能中断
- 8 个并发 DMAX 通道，每个通道具有独立的FIFO
- 灵活的命令链接（Command Linking）能力
- 支持含地址增量的一维传输
- 扩展传输能力：二维传输，回环传输，模板传输
- 支持TrustZone
- 支持特权、非特权传输

DMAX 主要包含以下模块：

**控制模块**

- 接收并终止来自处理器的 APB4 总线。
- 将寄存器访问转发至各个通道。
- 实现 DMA 的公共控制功能。

- 实现 DMA 控制器的功能单元，能够发起存储器传输。

- 终止来自外设的触发接口。
- 针对通道内部事件产生中断指示。
- 实现内部 FIFO，用于隔离通道的读写两侧。

**总线接口单元**

- 负责在 DMA 通道与一个或两个下游 AXI5 管理器接口之间进行流量路由与仲裁。

触发矩阵模块

- 在 DMA 通道的触发输入/输出端口与顶层触发输入/输出端口之间实现可选择的连接。
- 允许通道间进行内部触发。

# 2. DMA 控制器接口

本节包含 DMAX 接口的概览。

## 2.1 时钟与复位

DMAX 具有单一的时钟和复位域中。

APB4 配置接口使用时钟使能信号pclken，以支持在分频频率下运行。APB 配置接口使用  信号。

DMAX 使用单一的低电平有效复位信号 resetn。该复位必须与 clk 时钟信号同步释放，但可以异步置位。

DMAX 没有定义特殊的上电要求。

## 2.2 APB4 从机接口

APB4 从机接口用于访问 DMAX 的内部配置寄存器。

DMAX 支持 AMBA APB4 协议规范。有关更多信息，请参见 AMBA® APB Protocol Specification 文档。

**寄存器访问**

仅支持 32 位宽度的访问。当 APB4 写访问使用的 pstrb 不是 4‘b1111 时，会导致错误响应。非对齐访问通过在内部将 paddr[1:0] 固定为 0，从而被视为正常访问。

### 2.2.1 APB4 保护

APB4 寄存器空间中的某些寄存器受保护，仅供高特权级和安全软件模块使用。这些寄存器配置 DMA 控制器的整体行为，并通过检查访问的特权和安全属性在 DMA 控制器内部受到保护。

**特权保护**

在访问具有更高特权权利的寄存器时，DMA 控制器会检查 pprot[0] 位。当访问被拒绝时，DMA 控制器返回 RAZ/WI。

**安全保护**

通过在访问具有更高安全权利的寄存器时检查 pprot[1]，DMA 控制器支持安全扩展（Security Extension）。当访问违反安全规定时，DMA 控制器根据软件配置寄存器返回 RAZ/WI 或错误响应，并且如果使能了中断，还可能产生中断。

## 2.3 AXI5 管理器接口

DMA 控制器上存在两个具有相同属性的 AXI5 管理器接口。AXI5 管理器符合 AMBA AXI5 协议，具有缩减的 AXI5 特性集。有关协议的详细信息，请参见 AMBA® AXI and ACE Protocol Specification。AXI5 管理器接口用于由 DMA 通道生成的读写数据传输。

### 2.3.1 突发类型（仅限 FIXED / INCR）

DMAX 通过仅发送 FIXED 和 INCR 突发来降低复杂度。

FIXED 突发用于目标是带有 FIFO 的外设且多次访问同一地址的情况。这可以通过将增量值设置为 0 来实现。

INCR 突发用于所有其他情况，且突发长度受 \*MAXBURSTLEN 寄存器设置限制。如果 DMA 控制器在某些点连接到 AHB 互连，这也能降低将 AXI5 传输转换为 AHB 的复杂度。

### 2.3.2 ID 生成

**AxID** 的生成由 DMA 控制器按通道自动完成。读写传输使用标识通道的 **AxID**。命令链接也使用通道自身的 ID 从存储器中获取命令，但带有一个指示命令访问的额外侧带信号。可以通过使用 **CHID** 寄存器添加基于软件的通道 ID 设置，以辅助 DMA 控制器外部的内存映射。这些寄存器作为用户信号（User signals）存在于总线上，DMA 控制器内部不使用它们。

### 2.3.3 W 传输生成

**WDATA** 在 **AW** 通道传输的同时或之后发送到总线上。**WDATA** 不会赶超（overtake） **AW** 控制信息，因为这会增加仲裁逻辑的复杂度。如果传输大小设置为小于总线数据宽度，则使用 **Strobe**（选通）信号。

### 2.3.2.发起能力

读发起能力受每个通道独立 FIFO 深度的限制。通道只有在有足够空间存储完整的读响应时才会发起读操作。

写发起能力取决于传输大小和存储在通道内部 FIFO 中的数据。当 FIFO 包含带有所有节（beats）的完整突发时，发起写操作。

发起的传输数量取决于命令类型和地址对齐情况。

最大发起能力受 DMA 单元限制，以避免 AXI 基础设施因过多的 outstanding 传输而过载。软件可以控制总线上的在途传输数量。如果总线仍然过载，这可以实现调试和总线利用率整形。

### 2.3.5 响应处理

AXI 访问可能导致成功或不同的错误响应。错误响应会被路由到特定通道，该通道进入错误状态，而其他通道继续运行。

### 2.3.6 AXI 带宽利用率

本节提供术语定义和优化要求。

#### 术语定义

**突发断点 (Burst breakpoint)**

AXI5 突发不能跨越的边界，包括：

- 1KB 地址边界：DMAX 绝不跨越 1KbB 地址边界（支持 AHB 要求）。
- 触发块结束：流触发请求允许访问一个触发块。一旦访问完成，需要新的触发请求才能访问任何后续数据，因此 AXI5 突发不能超出触发块。
- FIFO 大小/2：限制单次突发传输的数据量。
- MAXBURST 寄存器设置：限制突发长度（axlen）：突发必须短于此用户指定值。

**非对齐起始 (Unaligned start)**

AXI5 事务访问的第一个字节不是总线的 LSB 字节通道。

**非对齐结束 (Unaligned end)**

AXI5 事务访问的最后一个字节不是总线的 MSB 字节通道。

#### DMAX 的两种模式

DMAX 有两种模式来确定其 AXI5 突发节的大小（axsize）：

**未优化 (Unoptimized)**

无论总线宽度如何，节大小与 DMA 命令中设置的大小相同。

**优化 (Optimized)**

为了优化窄传输的总线利用率，在可能的情况下将它们分组为更宽的访问。AXI5 协议规范为读侧和写侧提供了不同的可能性。

- 对于写侧，节大小与总线宽度相同，使用写选通（write strobes）从写操作中排除未访问的字节通道。
- 对于读侧，对于具有对齐结束的 AXI5 事务，节大小与总线宽度相同。具有非对齐结束的 AXI5 事务可能只能部分优化。参见“非对齐起始地址示例”和“非对齐结束地址示例”中的示例。

**优化要求**

- AXI5 突发目标必须是 Normal Memory 类型（非 Device 类型）。
- 当前侧的当前 DMA 命令必须禁用 Template 特性。
- 当前侧的当前 DMA 命令的地址增量必须为 1。
- 读操作：
  - AXI 事务要么包含足够的数据以达到总线对齐，要么具有对齐的起始地址。
  - 如果起始地址对齐，但数据不足以访问总线上的所有字节，则使用在 DMA 命令定义的地址空间内最大的可能 arsize。

### 2.3.9 传输属性

传输的存储器属性（Memory attributes）可以通过每个命令的软件可配置寄存器进行调整。安全和特权设置可以针对安全或特权通道进行调整。读侧和写侧可以分别选择设备（Device）或存储器（Memory）类型。缓存策略（Cacheability）和共享属性（Shareability）值也可以进行设置，以匹配 DMA 传输目标内存位置的设置。这些设置必须与系统中其他组件定义的值相匹配，并会影响每次传输的性能。

与命令链接（Command link）相关的读取始终作为指令类型传输发送，即 `arprot[2]` 驱动为 1。命令链接访问继承通道的安全和特权设置。

### 2.3.10 额外 AXI 信号

AXI 支持多种对 DMA 控制器运行而言可选的特性：

- **axsize** 信号受数据总线宽度的最大值限制，因此如果 DMA 控制器驱动的是 62.位或更窄的总线，则可能不会使用最高有效位（MSB）。
- 不使用 **axlock** 信号，因为 DMA 控制器不会生成独占（exclusive）或锁定（locked）传输。
- **axinner** 信号指示读写事务的内部域（inner domain）缓存属性。
- **axchid** 和 **axchidvalid** 信号指示软件可配置的通道 ID。
- **arcmdlink** 信号指示当前的读操作是命令链接读取。
- **axdomain** 信号增加了最小限度的 ACE5-Lite 兼容性。



## 2.4 触发接口

触发接口（Trigger Interfaces）可用于控制 DMA 通道操作与其他外设之间的交互。

外部外设或设备可以通过触发输入接口控制 DMA 命令的执行。

可以在 DMA 控制器内部将两个 DMA 通道连接在一起，或者通过串联多个 DMA 控制器进行连接。

除了硬件触发接口外，还通过通道控制寄存器提供软件触发接口，使软件能够与触发机制进行交互。

### 2.4.1 触发输入接口

触发输入接口可以同步 DMA 命令与外设的操作。外设可以在命令或命令的一部分可以开始时通知 DMAX。

该接口由简单的四相握手（4-phase handshake）以及定义当前请求和确认对类型的附加限定符总线信号组成。该接口定义为易于与现有的触发接口类型兼容。当接口跨不同的异步时钟域使用时，四相握手还允许简单的时钟域切换（CDC）结构。

### 2.4.2 触发输入接口信号

当外设将 req 信号拉高时，表示 DMA 控制器可以开始其命令或命令的一部分。DMA 控制器通过将 ack 置高来确认收到 req。

req 和 ack 信号都带有附加的限定符信号。这些信号为接收实体提供额外信息。

利用 reqtype[1:0] 信号，外设可以向 DMAX 提供更详细的信息。DMA 控制器使用 acktype[1:0] 信号在发送 ack 的同时向外设提供更多信息。

## 2.5 DMA 中断

中断指示 DMA 通道以及 DMA 单元内部状态的变化。每个通道都有自己独立的中断。始终存在一个全局非安全中断，此外，当启用 TrustZone 支持时，还会出现一个全局安全中断和一个安全违规中断。中断是电平触发信号。

## 2.6 状态接口

这些信号指示各个通道的不同状态：

- ch\_priv 显示通道的特权设置
- ch\_nonsec 显示通道的安全设置

# 3. DMA 控制器运行

## 3.1 DMA 控制器运行概览

DMA 控制器可以通过寄存器写入进行配置，以执行各种命令。当软件完成寄存器设置和命令链接元素后，可以通过额外的寄存器写入来使能通道。这一步会使所有配置寄存器在软件侧变为只读。随后，DMA 控制器开始检查命令的有效性，并根据寄存器设置执行传输。

命令可以包含简单的存储器传输、离散-集中型（scatter-gather）传输、触发处理、通用输出、2D 存储器操作以及许多其他组合。当命令执行完毕时，DMA 控制器要么返回空闲状态，要么重新加载该命令，或者跳转到命令列表中的下一个项目。当 DMA 控制器返回空闲（IDLE）状态时，它可以产生中断和触发输出信号，以便将此事件与系统中的软件或其他硬件元件同步。当 DMA 控制器处于空闲状态时，可以再次配置寄存器。

DMA 控制器还具备检测存储器传输期间错误的能力。当接收到故障时，它会返回错误并停止运行。

## 3.2 DMA 控制器运行基本命令

本节包含 DMAX 运行基本命令的概览。

### 一维传输 (Transfer type 1D)

一维传输按照配置的传输大小，将数据从源地址连续传输到目的地址。此模式是大块数据传输的典型用例，在 DMA 控制器传输过程中不需要进行数据格式化。

传输大小设置范围从字节到总线宽度，按 2 的幂次方递增。源端和目的端的传输大小相同。源地址和目的地址与传输大小对齐，因为根据 TRANSIZE 的值，低位地址位会在内部被忽略。要复制的传输数量以传输大小的增量来指定。软件还可以限制 DMA 控制器发送到总线的最大突发长度，以允许互连上的其他设备进行仲裁。

一维回绕模式中，`XTYPE` 设置定义了 DMA 控制器将源数据拷贝到目的端时的行为。选项如下：

**wrap mode（回绕模式）**

  启用回绕，源数据会被多次拷贝到目的端。一维操作类型：1Dwrap。
- fill
  启用填充，当源数据耗尽时，目的端将使用预定义模式进行填充。一维操作类型：1Dfill。

#### 3.2.2 一维回绕情况列表

一维回绕传输可能出现以下几种情况：

##### SRCXSIZE == 0, DESXSIZE == 0

DMA 控制器传输不启动。可能仅处于等待触发信号的状态。

##### SRCXSIZE == 0, DESXSIZE > 0

- continue, wrap：无事发生，不执行读或写操作。
- fill：目的端填充预定义的填充值（fill value），因此仅发生写操作。

##### SRCXSIZE > 0, DESXSIZE == 0

- continue, wrap, fill：不发生写操作。DMA 控制器仅发送 `SRCXSIZE` 次数的读传输。

##### SRCXSIZE == DESXSIZE

无论 `XTYPE` 设置为何值，本质上都是标准的 1D 操作。

##### SRCXSIZE > DESXSIZE

由于目的端没有足够空间容纳源内存内容，当目的端范围填满时拷贝停止。不会发生覆盖，多余的数据在 DMA 控制器内部被丢弃。

##### SRCXSIZE < DESXSIZE

- continue：当源端数据耗尽时，DMA 控制器停止数据拷贝。执行 `SRCXSIZE` 次数的读操作和写操作。
- wrap：当到达源数据末尾时，源地址计数器跳转回原始起始地址，并开始将相同的源数据拷贝到所有必要的目的内存位置。在整个回绕操作期间，源内存位置会被多次读取，因此源数据需保持不变（使用流接口时除外）。即使 `SRCXSIZE` 较小，本质上也会执行 `DESXSIZE` 次数的读和写。
	- 注意：单凭 `SRCXSIZE` 和 `SRCADDR` 的状态无法确定已执行的读取次数，必须根据 `DESXSIZE` 和 `DESADDR` 的进度来计算。
- fill：向所有剩余的目的位置插入填充值。填充值由额外寄存器定义，并使用对应的传输位宽部分。读操作次数等于 `SRCXSIZE`，填充值在 DMA 控制器内部生成，总计产生 `DESXSIZE` 次写操作。

##### DESXADDRINC = 0

特殊回绕案例。 此设置表示目的地址不递增（通常用于目标为 FIFO 的场景），因此不会发生实际的地址回绕。

- continue：源数据耗尽时停止。执行 `SRCXSIZE` 次数的读写。
- wrap：由于目的地址不递增，源数据会根据 `SRCXSIZE` 和 `DESXSIZE` 的比例多次拷贝到目的 FIFO。源数据被重复读取，数据在目的 FIFO 中循环。
	- 示例：若 `SRCXSIZE` 为 3，`DESXSIZE` 为 8，目的 FIFO 数据如下：
		1. `des_data[0] = src_data[0]`
		2. `des_data[1] = src_data[1]`
		3. `des_data[2] = src_data[2]`
		4. `des_data[3] = src_data[0]`
		5. `des_data[4] = src_data[1]`
		6. `des_data[5] = src_data[2]`
		7. `des_data[6] = src_data[0]`
		8. `des_data[7] = src_data[1]`
- fill：传输结束时，将填充值拷贝到 FIFO。

在使用二维回绕时，`XTYPE` 设置也用于处理每一行的回绕类型。它还支持将数据流从源端的一行连续流动到目的端的不同行中。

- continue：当达到 `SRCYSIZE` 时停止拷贝。
- wrap：地址计数器发生回绕，开始将源数据的开头部分拷贝到目的内存的剩余位置。

### 3.3.3 模板化传输（Templated transfers）

模板化传输功能允许 一维传输根据预定义的模式选择性地拷贝数据。这些模式通过模板寄存器定义，描述了要传输地址的重复位掩码（Bit-mask）。

> fig 5.14

位掩码定义在模板寄存器 `SRCTMPLT` / `DESTMPLT` 中。源端和目的端拥有独立的模板寄存器以及用于定义模板长度的模板尺寸字段。源端和目的端可以独立配置。

模板寄存器的最低位固定为1。这意味着传输开始时不能有初始间隙，在 `SRCADDR` / `DESADDR` 定义的起始地址处始终会发生数据传输。如果确实需要初始间隙，则必须偏移地址，使首次实际传输点位于起始地址处。

实际模板尺寸计算公式为：
$$
\text{Actual Template Size} = \frac{SRCTMPLTSIZE+1}{DESTMPLTSIZE+1}
$$
默认设置（全 0）表示禁用模板化功能。通过将模板尺寸设置为大于 0（即 SRCTMPLTSIZE > 0 或 DESTMPLTSIZE > 0）来启用该功能。模板寄存器中超出定义模板尺寸的高位位掩码将被忽略。

#### 地址计算

模板化传输功能始终使用单次传输来搬运数据，它不会尝试将连续的传输合并为突发传输。在每个周期内，硬件都会为该传输计算一个新地址。

## 3.4 DMA 控制器操作触发器

触发输入和输出可以在无需软件干预的情况下同步系统内的活动。启用后，DMA 控制器可以基于通道配置触发输入和输出。输入触发支持多种模式以满足不同需求，而输出触发通常用于标记完整 DMA 控制器操作的最后一步。DMAX 的触发矩阵 (Trigger Matrix) 负责处理外部触发端口与 DMA 通道之间的连接，使 DMA 通道能够选择使用哪些触发端口，或连接到其他 DMA 通道。

### 3.4.1 触发输入 (Trigger Inputs)

触发输入端口利用触发信号使外设能够与 DMA 控制器通信，并在无需软件干预的情况下安排 DMA 控制器操作的顺序。触发器为 DMA 控制器操作内的传输提供流控制 (Flow Control)，也可用于启动整个 DMA 控制器操作。触发输入的具体使用模式可通过配置寄存器进行选择。

外设与 DMAX 之间采用 4 相位握手总线 (4-phase handshake bus)。额外的限定信号在两个方向上扩展了 `req` (请求) 和 `ack` (应答) 信号对。

- 请求端：外设通过 `req` 信号告知 DMA 控制器有数据待传输。
- 请求类型 (`reqtype`)：用于指示传输类型（单次或块传输）以及是否为最后一批数据。

> tab 5.4

DMAX 通过 `ack` 信号告知外设已收到请求。应答类型 `acktype` 提供额外信息，说明请求是否被接受，或 DMA 控制器传输是否在当前事务后结束。

> tab 5.5

启用后，一个通道拥有两个触发输入端口：

1. 源端触发 (Source Triggering)：控制读上操作。
2. 目的端触发 (Destination Triggering)：控制写操作。

触发输入的数量是可配置的，可以与通道的数量不同。软件可以使用触发矩阵为通道选择触发输入，可选择的源参见"触发矩阵"。

当存在触发端口但软件希望禁用触发时，可以在控制寄存器中将该命令的触发设为未使能模式。在此模式下，DMA 通道不会等待任何外部输入的发生，而是在设置 DMA 控制器使能位后立即开始执行。

触发输入模式通过软件可编程寄存器进行设置。触发相关寄存器只能在 DMA 通道空闲时调整。

触发输入在 DMA 通道使能后连接到该 DMA 通道。这些连接会一直保持到当前命令持续期间。当所有操作完成后，触发会被交还给触发矩阵。

当通道完成一个命令时，该通道所使用的触发输入端口上可能存在一个挂起的请求。这种情况可能发生在：某个触发请求在命令已经接收到所有预期的触发请求之后、且在触发输入被交还给触发矩阵之前到达。

顶层触发端口上的请求信号将保持挂起状态，而得不到应答信号。类似地，当请求信号到达一个未连接到任何通道的触发输入时，它也得不到应答信号， 请求信号保持挂起。当某个通道被配置为使用一个带有挂起请求的触发输入端口时，该通道会在通道使能后立即接收到该请求信号 。

在正常操作中，DMA 通道会在触发操作完成后释放输出触发。如果通道收到停止信号，且触发端口上已存在一个挂起请求，则通道会立即释放该端口，而不等待 req-ack 握手完成。此时通道已准备好被配置以执行新命令。然而，DMA 会等待触发端口上的握手完成，在此之前其他通道无法选择该端口。

当通道被暂停时，挂起的触发保持原样，服务处于挂起状态。接口可能在任意状态下停滞。在暂停期间，外部信号（如触发输入上的请求信号或触发输出上的应答信号）可能发生状态变化。当通道操作恢复后，触发操作继续进行。

当 DMA 通道被停止时，触发矩阵重新取回对触发输入的控制权。在将控制权交还给矩阵之前，通道会先服务一个已被应答的触发。接口可能停留在 idle 或 request 状态。对于触发输出，触发矩阵重新取回控制权，并通过一个内部 应答信号响应该通道已挂起的触发。对于挂起的外部触发，则必须由触发矩阵通过等待 应答信号到达来加以服务。应答信号到达后，请求信号被拉低，接口返回 idle 状态。

软件可以发起触发请求的自动清除。DMA 控制器可以对触发输入上的挂起请求发送一个拒绝应答。通过这种方式，可以在不违反触发协议的情况下清除不需要的挂起请求。

出于调试目的，软件可以模拟外部硬件触发。更多信息参见"软件触发"。

#### 3.4.1.1 触发输入命令模式

触发输入可用于启动完整的 DMA 命令。当源端或目的端被设置为此模式时，即使 DMA 通道的使能位已置位，DMA 命令也会在开始任何内存操作前等待触发握手。DMA 控制器会等待源端和目的端的请求同时有效后才进行应答，以此指示命令正式启动。

> fig 5.15

图中显示，先收到目标端触发请求。在 DMA 控制器同时检测到源端触发请求之前，它不会被应答。此时，源端和目标端触发都被应答，DMA 控制器传输即可开始。触发握手可以在不同的时间点返回 IDLE，具体取决于请求信号的驱动方，但这不会干扰数据传输的执行。然而，只有当两个触发应答信号都被撤销后，命令才能结束。

当源端或目标端任一侧被设为命令模式触发时，DMA 通道操作会等待触发握手发生（ack 拉高）才开始操作。在握手完成之前，DMA 控制器处于活动等待状态，不向总线接口发送传输。当所有基于命令的触发输入握手都完成后（即 req 和 ack 均为高），命令执行即可开始，DMA 通道退出等待状态。在整个 DMA 控制器操作持续期间，DMA 控制器不接受新的触发请求。

对于命令模式触发，reqtype[1:0] 可取以下任意值：SINGLE / BLOCK / LAST SINGLE / LAST BLOCK。

acktype[1:0] 的 OKAY / LAST OKAY 两个值对命令模式触发均有效。DMA 返回 OKAY 值。在命令触发情况下，不使用 DMA 通道 acktype[1:0] 的 DENY 值。

源端和目标端都可以设为硬件/软件控制的命令模式。在此模式下，DMA 通道等待触发以开始操作。触发输入主要为外部硬件触发。

不过，可以通过写入软件可编程寄存器生成内部触发请求事件，从而覆盖输入触发请求。当任一类型的触发到达时，DMA 通道即开始其操作。如果在命令已经运行时到达一个软件触发，则不发生任何动作。如果在软件已请求触发时到达一个硬件触发，则该硬件触发保持挂起。当两者同时到达时，硬件触发会被服务。

当命令触发的触发请求被撤销时，DMA 控制器会尽快撤销应答。这使得触发的发送方可以继续其操作。

> fig 5.16

- t0：触发接口处于 IDLE（空闲）。
- t1：外设请求任意类型的触发以启动命令。
- t2：如果 DMA 通道正在等待触发并准备好执行操作，DMA 控制器接受请求（ack 拉高）。
- t3：外设在收到 DMA 控制器的 OKAY 响应后撤销 `req` 信号。此时 DMA 控制器仍在执行请求的操作。
- t4：DMA 控制器检测到 `req` 已撤销，随后撤销 `ack`，触发接口返回 IDLE。此时命令仍在运行。
- t5：命令执行完毕，但这不会反映在触发输入接口上。

#### 3.4.1.2 触发输入流控制模式

触发输入还可用于流控制目的，即每次触发仅使能大型命令中的一小部分传输。在此模式下，软件必须设置触发尺寸，它规定了每次触发事件所允许访问的“传输位宽块”的数量。源端触发输入用于控制读流，而目的端触发输入则控制 DMA 操作的写流。

> fig 5.17

图中显示，读传输只有在收到目标端命令触发以及源端触发之后才能开始。目标端的写操作只有在从源端收到足够的数据后才能开始。

当源端触发被设为流控模式时，DMA 通道的读操作会停滞，直到收到第一个触发请求。

> fig 5.18

图中显示，尽管目的端触发请求先到达，但命令仍必须等待源端触发到达。在接收到源端命令触发后，读传输立即开始。只有在接收到目的端触发且有足够数据待发送时，写操作才会开始。DMA 控制器会在其内部 FIFO 中预加载数据，以便在接收到下一个目的端触发时，写操作能尽快发生。

当设置了目的端触发时，DMA 通道的写操作将停滞，直到接收到第一个触发请求。在目的端触发握手完成之前，读操作可以先行启动并填满 FIFO。

一旦接收到触发输入请求，命令执行即可开始，且 DMA 通道退出等待状态。DMA 控制器仅访问由块大小寄存器指定的传输数量作为最大值。直到完成块大小数量的传输（最后一个块允许较小）并收到最后一次传输的响应后，DMA 控制器才会拉高触发应答。

DMA 通道在断言应答之前，会等待所有响应事务到达。握手必须返回空闲状态，状态机才能返回“等待触发”或“完成”状态。由于地址生成逻辑会停滞直到收到最后的响应，这增加了触发之间的延迟。然而，这也能避免外设侧并行触发应答与 AXI 传输之间的时序冲突。

可以设置 DMA 通道，使源端和目的端均允许 DMA 控制器流控操作。在此模式下，DMA 通道会统计传输数量，并在达到要求数量时结束通道操作。当仍有待传输块时，DMA 通道向外设发送 OKAY ACK；当到达最后一个传输块时，发送 LAST OKAY ack。

> fig 5.19

- t0：触发接口处于 IDLE。
- t1：外设请求 BLOCK 或 SINGLE 触发类型。
- t2：DMA 控制器尽快开始执行请求；到 t2 时，该操作请求的所有传输均已完成。
- t3：外设在收到 DMA 控制器的 OKAY 响应后撤销 `req` 信号。
- t4：DMA 控制器完成请求服务，并在准备好接受新请求时撤销 `ack` 信号。

### 3.4.2 用于源选择的触发矩阵

DMAX 为触发输入和输出实现了触发矩阵，每个触发都可以根据寄存器设置分配给特定通道。触发矩阵还可以在一个通道的触发输出端口与另一个通道的触发输入端口之间建立连接，从而利用内部事件启动触发。

触发输入的数量是可配置的，且可以与通道数量不同。软件能够通过触发矩阵为通道选择触发输入。

DMAX 管理选择过程，仅允许触发器与通道之间的有效连接。硬件会检查通道和触发端口的安全属性，并且一个触发端口不能同时被多个通道选择。在某些场景下，外部触发端口虽未被选择，但由于软件干预仍处于处理请求的状态，这些场景也由矩阵覆盖，直到软件干预的副作用清除后，触发端口才变为可选状态。

如果由于以下原因导致触发输入接口不可选，则选择操作会报错：

- 该接口已被另一个通道占用。
- 触发端口未被选择，但有多个通道尝试在同一个周期内选择它。
- 由于安全属性差异而不允许选择。
- 触发输入接口由于正在进行软件发起的清除握手而未处于 IDLE 状态。
- 使用内部触发时，触发输入端口不能连接到同一个通道的触发输出端口。

如果由于以下原因导致触发输出接口不可选，则选择操作会报错：

- 该接口已被另一个通道占用。
- 触发端口未被选择，但有多个通道尝试在同一个周期内选择它。
- 由于通道与触发端口的安全属性差异而不允许选择。
- 触发输出接口由于之前未完成的触发握手而未处于 IDLE 状态，可能是由于 pending 的 `req` 未收到 `ack`，或者握手结束时 `ack` 卡在高温状态。
- 使用内部触发时，触发输出端口不能连接到同一个通道的触发输入端口。

### 3.4.3 内部触发连接

DMAX 通过内部触发连接实现两个通道的同步。一个通道（发送通道）的触发输出端口可以内部连接到另一个通道（接收通道）的触发输入端口。触发输出端口上的 `req` 信号标志着一个命令的结束，并启动接收通道上另一个命令的操作。

使用内部触发的通道始终处于命令触发模式，无论配置的触发类型为何。

发送通道会等待来自接收通道的触发 `ack`。当接收通道配置为命令触发时，`ack` 会在发送通道撤销 `req` 后立即撤销。这意味着当接收通道开始其命令时，发送通道可以继续执行新的命令。

可以形成由两个以上通道通过内部连接触发而构成的链条。这些连接的通道甚至可以组成一个闭环。在这种情况下，可以使用软件触发来启动链条中的第一次操作。

### 3.4.4 软件触发

软件触发接口允许软件直接与 DMA 控制器的触发逻辑进行交互。它通常用于软件与 DMA 控制器操作的同步，或者在开发阶段作为硬件触发事件的替代方案。

#### 3.4.4.1 软件触发接口

软件触发接口由以下 DMA 通道寄存器位域组成：

CH<x>\_CMD 寄存器中的软件触发控制字段：

• SRCSWTRIGINREQ
• SRCSWTRIGINTYPE
• DESSWTRIGINREQ
• DESSWTRIGINTYPE
• SWTRIGOUTACK

CH<x>\_STATUS 寄存器中的软件触发状态字段：

• STAT\_SRCTRIGINWAIT
• STAT\_DESTRIGINWAIT
• STAT\_TRIGOUTACKWAIT

CH<x>\_STATUS 寄存器中的软件触发中断状态字段：

• INTR\_SRCTRIGINWAIT
• INTR\_DESTRIGINWAIT
• INTR\_TRIGOUTACKWAIT

CH<x>\_INTREN 寄存器中的软件触发中断使能字段：

• INTREN\_SRCTRIGINWAIT
• INTREN\_DESTRIGINWAIT
• INTREN\_TRIGOUTACKWAIT

#### 3.4.4.2 软件触发协议

等待状态字段（STAT_\*WAIT）指示 DMA 通道何时可以接受软件触发。当等待状态字段为零时，无法发起软件触发。

##### 软件触发输入协议

所需的触发输入类型必须在 \*SWTRIGINTYPE 字段中设置。通过向 \*SWTRIGINREQ 字段写入 1 来发起触发输入请求。这可以在设置类型的同一次寄存器写访问中完成，也可以在随后的一次写访问中完成。

当请求发起后，相关的 STAT_\*TRIGINWAIT 标志被清除，以表明请求的处理已经开始。\*SWTRIGINTYPE 字段变为只读，以在整个触发事件期间保持触发输入类型稳定。

当触发请求完成后，\*SWTRIGINREQ 字段被清除，\*SWTRIGINTYPE 字段重新变为可读/写。

##### 软件触发输出协议

STAT_TRIGOUTACKWAIT 字段指示存在一个活动的触发输出请求，软件可以通过向 SWTRIGOUTACK 字段写入 1 来向其发送应答。

当应答被接受后，STAT_TRIGOUTACKWAIT 状态字段被清除。

#### 3.4.4.3 软件触发中断

每当对应的 STAT_\* 字段被置位、且对应的中断通过将 INTREN_\* 设为 1 而被使能时，INTR_\* 中断状态字段就会被置位。

当状态标志被清除时，中断标志会自动清除。

## 3.5 DMA 通道生命周期

**禁用状态（Disabled state）**

复位后，通道处于禁用状态。必须通过配置通道寄存器来设置待执行的命令。在此状态下，软件可以修改每一个可写的配置寄存器。

通道配置完成后，通过设置 CH<x>\_CMD 寄存器中的 ENABLECMD 位来启动执行。

**使能状态（Enabled state）**

命令的执行发生在使能状态。当 ENABLECMD 位被置位时，ch\_enabled 信号被拉高，以指示命令正在执行。该状态信号会一直保持为高，直到命令完成且没有配置其他链接命令，或者通道操作被手动停止或因错误事件而停止。

在使能状态下，通道的所有配置寄存器都变为由硬件控制。软件仍可读取这些寄存器，但硬件会在命令执行的整个过程中更新其内容。在命令执行期间，软件唯一可以调整的寄存器是 CH<x>\_CMD、CH<x>\_STATUS 和 CH<x>\_WRKREGPTR，它们允许软件停止或暂停命令执行、清除中断以及检查内部工作寄存器的状态。

以下大小（size）和地址（address）寄存器在数据传输期间会持续更新，以显示传输的当前状态：

- CH<x>\_SRCADDR / CH<x>\_SRCADDRHI
- CH<x>\_DESADDR / CH<x>\_DESADDRHI
- CH<x>\_XSIZE / CH<x>\_XSIZEHI
- CH<x>\_YSIZE

\*ADDR 寄存器指向内存中下一个将要访问的位置。\*SIZE 寄存器从起始值递减到 0，读取时显示剩余的传输次数。计数器的值无法明确表明命令已经完成，因为 2D 或回绕（wrap）操作可能会重启计数器或提前结束。

命令执行在以下情况下结束：

- 命令成功完成。
- 发生错误事件（例如配置错误）导致命令停止。
- 因设置 CH<x>\_CMD 寄存器中的 DISABLECMD 位而禁用了通道。
- 通道因以下原因被停止：
  - 设置 CH<x>\_CMD 寄存器中的 STOPCMD 位
  - 设置 NSEC\_CTRL / SEC\_CTRL 寄存器中的 ALLCHSTOP 位（取决于通道配置的安全属性）

当上述任一条件导致命令结束执行时，通道返回禁用状态。返回禁用状态时会设置状态标志（CH<x>\_STATUS 寄存器中的 STAT\_\* 字段）。软件可以检查这些状态标志，以确定执行是成功还是发生了错误。

**暂停状态（Paused state）**

当发出暂停请求时，通道进入暂停状态。暂停请求可通过以下方式发出：

- 设置 CH<x>\_CMD 寄存器中的 PAUSECMD 位（软件暂停请求）。
- 设置 NSEC\_CTRL / SEC\_CTRL 寄存器中的 ALLCHPAUSE 位（取决于通道配置的安全属性）。
- 自动软件暂停请求：当 STAT\_DONE 标志被置位、且通道已通过设置 CH<x>\_CTRL 寄存器中的 DONEPAUSEEN 位而预先配置为使能完成暂停（done-pause）时。
- 交叉触发接口（Cross Trigger Interface）。
- 热复位（Warm reset）。

在暂停状态下，通道执行被停滞。总线事务被停止，触发的处理也被暂停。软件可以在暂停期间检查通道状态，因为地址和大小寄存器反映了通道的当前状态。也可以通过设置 CH<x>_WRKREGPTR 并读取 CH<x>_WRKREGVAL 寄存器来检查内部通道寄存器。

当暂停请求被撤销时，通道恢复执行：

- 软件暂停请求（包括完成暂停）可通过设置 CH<x>_CMD 寄存器中的 RESUMECMD 位来撤销。

在暂停状态下，可以通过发出停止命令来停止通道。

在暂停状态下，通道仍保持使能（ch_enabled 拉高），只是执行被临时停止。暂停时配置寄存器仍保持只读。


### 3.5.1 命令执行状态 (Command Execution States)

每一个 DMA 命令都包含多个按固定顺序执行的步骤。根据配置的不同，某些步骤可以被跳过。

> fig 5.22

**配置检查状态**

验证通道的寄存器配置。如果检测到无效的寄存器值或配置冲突，硬件将置位错误状态位并停止通道运行。

**触发分配状态**

如果配置了外部硬件触发或内部触发，在此状态下建立物理触发端口与通道的连接。

- 连接失败：若无法建立连接（如权限冲突或端口被占用），将指示触发选择错误并停止运行。
- 跳过：若配置为软件触发或无触发，则忽略此步骤。

**命令触发状态**

处理命令模式下的输入触发请求：通道执行保持停滞，直到所有设为命令模式的触发输入都接收到请求。只有当所有请求都收到后，硬件才会断言触发应答。

**数据传输状态**

执行实际的数据搬运。流控触发仅在此状态下进行处理。

**完成状态**

到达此状态表明命令已成功完成。触发连接被释放，STAT\_DONE 标志根据所配置的 DONE\_TYPE 字段被置位。

如果在此之前已发出 DISABLECMD，则通道执行结束，STAT\_DISABLED 标志被置位。

如果 CMDRESTARTCNT 非零或 CMDRESTARTINFEN 被置位，则当前命令自动重启。如果 CMDRESTARTCNT 计数器非零，则将其减 1。

如果未配置当前命令的自动重启，则检查 LINKADDREN 标志。如果被置位，则命令链接功能被使能，使用 LINKADDR 指针抓取下一个命令。

命令链中的每个命令都可以选择输入和输出触发。连续的命令不一定选择相同的触发。无论如何，在命令链执行期间，触发会在每个命令处重新连接。

当通道已收到它所预期的最后一个触发之后，又有一个触发输入请求被发送到该 DMA 通道时，该触发请求会保持挂起。下一个被配置为使用相同外部触发端口或内部通道的命令会接收到它。如果新的链接命令使用这个相同的触发，则下一个命令可以响应它，不会丢失任何触发事件。

如果自动重启和命令链接都被禁用，则通道操作结束，通道返回禁用状态。

否则，检查 DONEPAUSEEN 标志。如果被置位，则通道执行暂停，直到收到 RESUMECMD。

### 3.5.2 命令自动重启



自动重启功能通过消除对同一命令的不必要重新加载，在单个命令必须在循环中重复多次时提高了效率。

自动重启可通过将 MDRESTARTINFEN 或 CMDRESTARTCNT 字段设为非零值来使能。迭代次数取决于这些字段的设置：

- CMDRESTARTINFEN 被置位：自动重启以无限循环方式持续进行，直到通道被禁用或停止。
- CMDRESTARTINFEN 未置位：自动重启按 CMDRESTARTCNT 字段中配置的次数进行。如果配置为零，则不使能自动重启功能。

如果使能了自动重启功能，则目标地址、源地址以及传输大小设置会根据 REGRELOADTYPE 字段的设置重新加载为其原始值。如果某个地址未被重新加载，则命令执行下一次迭代的起始地址将基于操作类型来确定。

### 3.5.3 错误处理 (Error Handling)
DMAC 操作期间可能发生四种类型的错误：

- 操作期间的 AXI5 总线错误
- 配置错误
- 触发分配期间的触发选择错误

这些错误中的任何一个都会导致 DMA 通道停止其操作。当通道状态转换到 DISABLED（ch\_enabled = 1'b0）时，CH<x>_STATUS 寄存器中的错误状态标志 STAT_ERR 被置位。

如果相关的中断使能标志 INTREN\_ERR 被置位，则中断标志 INT\_ERR 也会被拉高。

错误原因在 CH<x>\_ERRINFO 寄存器中指示，当 STAT\_ERR 被置位时该寄存器包含有效信息。

**AXI5 总线错误 **

当检测到总线错误时，当前 DMA 命令立即停止，与该总线错误相关联的数据被丢弃。所有未完成（outstanding）的事务都会被完成，但其数据也会被丢弃。如果 BUSERR 标志被置位，则 CH<x>_ERRINFO 寄存器中的 AXIRDRESPERR、AXIWRRESPERR 或 AXIRDPOISERR 中至少有一个也会被置位，以指示总线错误状况的来源。

**配置错误**

配置错误在数据传输执行之前进行检查。当检测到配置错误时，不会发起任何总线传输。

配置错误的三种可能来源为：

- 无效的命令链接头（LINKHDRERR）——所有位读取为零。
- 在配置寄存器中设置了非法的字段值（REGVALERR）。
- 配置寄存器中存在不兼容的设置（CFGCONFLERR）。

**非法字段值错误**

非法字段值错误（REGVALERR）的原因为：

- TRANSIZE 字段大于总线数据宽度。
- 触发选择器（SRCTRIGINSEL、DESTRIGINSEL、TRIGOUTSEL）的值超出有效范围。

**不兼容设置错误**

配置设置冲突（CFGCONFLERR）的原因为：

- 触发输入配置与所配置的传输模式（XTYPE / YTYPE 或 stream 设置）冲突。
- 模板化传输（templated transfer）配置在不受支持的传输模式下。
- AXI-Stream 接口在不受支持的传输模式下被使能。

有关不兼容设置的详细条件，参见"配置"。

**触发输入选择错误（Trigger in selection errors）**

这些错误可能在触发分配状态期间发生——当所选的触发端口或通道在选择的时钟周期不可用时。触发分配失败后命令执行停止，因此不会发起任何总线传输。触发端口或通道不可用的可能原因为：

- 配置外部触发时，所选的触发端口已被另一个通道使用。
- 配置内部触发时，所选的通道已连接到另一个通道。
- 源端和目标端选择了相同的触发。

### 3.5.4 命令执行状态报告

在 DMA 命令执行后，软件可以读取 X、Y 尺寸寄存器以及地址寄存器的内容。

这些寄存器的内容取决于 DMA 命令停止的方式：

达到 DONE 状态（命令执行已完成）：

  - 尺寸寄存器均为 0，读端或写端均无待完成的事务。
  - 地址寄存器包含“下一个”地址，其值就如同该已完成命令之后紧跟着相同类型的后续 DMA 控制器操作一样。

处于 STOPPED/PAUSED 状态（命令执行在完成前被停止或暂停）：

  - 尺寸寄存器包含当前未完成事务的实际坐标（Coordinates）。
  - 地址寄存器包含下一个未完成事务的地址。

在 STOPPED/PAUSED 状态下，地址和尺寸寄存器的值仅是实际命令执行状态的近似值，可能并不包含精确位置。它们仅作为命令执行大约在何处被中止的提示。

如果暂停发生在命令链接执行期间，读回的寄存器可能包含不一致的命令信息，因为当 DMA 进入暂停状态时，并非所有寄存器都已完成更新。

如果某个方向未参与命令执行，则该方向的读/写地址保持不变。

例如，当某个 DMA 命令中写有效但读无效时，读地址不变，而写地址按上述行为变化。

#### 命令结束时的 size 寄存器

size 寄存器包含当前行内最后一个未处理事务的坐标。当 DMA 命令完成时，两个 size 寄存器均为 0。

当停止或总线错误中断 DMA 命令时，1D 命令只有 X 寄存器，其中以 Transize 为单位包含剩余未发送的 DMAC 事务。

2D 命令有 X 和 Y size 寄存器，其中包含下一个未发送事务的 X 和 Y 坐标：

- 当 DMA 命令处于行中（mid-line）时，X 和 Y size 包含下一个未发送数据的未发送坐标。
- 当 DMA 命令已完成当前行时，取决于中断事件的时序，以下两种坐标都有可能。这两种坐标是等价的，因为它们指示了 DMA 命令未传输的相同数据量。
  - Y：当前行号，X：0
  - Y：下一行号，X：该行的总 X size

此外，在 DMA 命令开始时，X 和 Y size 可针对某些 Y 和 X 配置进行优化：

- 如果 X type 为 WRAP 或 FILL 且目标 X size < 源 X size，则将源 X size 设为目标 X size。
- 如果 X type 为 WRAP 或 FILL 且 Y type 为 FILL 或 CONTINUE，且源 Y size > 目标 Y size，则将源 Y size 设为目标 X size。

这些优化有助于减少不必要的读操作——这些操作已可从 DMA 命令配置中预测出来。

#### 空命令后的 size

如果发生空命令执行，则 DMA 命令结束时 size 不变。如果一侧参与命令执行而另一侧保持空闲，则命令完成时空闲侧的 size 寄存器变为零。


## 3.6 命令链接 (Command Linking)

命令链接功能使 DMA 通道能够通过自动地将下一个命令从系统内存加载到其配置寄存器中，从而执行更多操作。此功能使 DMA 控制器在一次事务中组合多个命令变得灵活多样。每个命令都可以定义新的传输参数、触发行为和中断设置。这为 DMA 单元的使用提供了极大的灵活性，并使得通过合理设计命令链来实现复杂的数据传输任务成为可能。

命令由存储在内存中的描述符定义。通道使用存储在链接寄存器（LINKADDR）中的指针地址来抓取描述符。第一个命令必须直接设置在通道寄存器中，以启动链接命令链。如有需要，第一个命令可以是一个空命令，仅指向包含第一个非空命令的内存位置。

某些命令可能只更改部分配置寄存器，例如目标地址或传输次数，而对下一个命令保持所有其他寄存器不变。为此，内存中的命令描述符有一个头部，用于指定要更新通道寄存器组中的哪些寄存器。这减少了命令抓取期间执行的总线传输次数。

当命令链中某个命令未设置 LINKADDREN 位时，命令链接链结束。这可以通过在链中最后一个命令的描述符中不设置该 LINKADDR 寄存器位来实现。

当一个命令完成后，新命令在 DONE 状态之后被抓取，参见"通道生命周期"。寄存器值根据头部字被读取和更新。

可以通过设置通道命令寄存器（CH<x>\_CMD）中的 DISABLECMD 位来停止命令链的执行。它可用于停止无限循环的命令链接。禁用会干净地停止命令链；当前正在执行的命令会被完成，但不会加载下一个命令。

当命令链接中的某个命令被暂停时，其行为与暂停单个命令完全相同，参见"停止和暂停控制"。恢复后，该命令的执行被恢复，命令链接继续进行。

当命令链接中的某个命令被停止时，该命令的剩余部分以及命令链接的剩余部分都被取消。停止会等待读写事务的所有未完成响应，但它会尽快尝试完成通道操作。更多信息参见"停止和暂停控制"。

### 3.6.1 命令结构

命令以链表数据结构存储在系统内存中。每个命令都包含关于必须更新哪些 DMA 通道配置寄存器的信息，以及一个指向下一个命令的指针。

指向下一个命令的指针存储在 CH<x>\_LINKADDR / CH<x>\_LINKADDRHI 配置寄存器中。这些寄存器可以像任何其他通道配置寄存器一样由下一个命令更新。

通过禁用 CH<x>\_LINKADDR 寄存器中的 LINKADDREN 标志（第 0 位）来终止命令链。所有其他命令都必须使能该标志，以指示一个有效的链接地址。

命令链的第一个命令必须在通道配置寄存器中手动设置。第一个命令可以为空，仅链接到链中第一个真实命令。

### 3.6.2 加载命令

命令链接功能使用与数据传输相同的 AXI 总线 manager 接口，从系统内存加载命令。

**命令描述符抓取属性**

通道用于命令抓取的 AXI ID 与用于数据负载的相同。

命令通过 AXI burst 读从内存中抓取，其 TRANSIZE 参数设为 DATA\_WIDTH 参数的值，\*MAXBURSTLEN 字段设为最大值。

命令链接读使用通道的安全和特权状态，与 CH<x>\_SRCTRANSCFG / CH<x>\_DESTRANSCFG 寄存器中设置的传输属性无关。因此，非安全（Non-secure）通道只能加载非安全命令，安全（Secure）通道只能加载安全命令。

在 AXI 总线上，命令链接读通过将 arprot\_m<x>[2] 设为 1（指令访问）与数据传输区分开来。AR 通道上还额外添加了一个 User 信号 arcmdlink_m<x>，用于指示该读属于命令链接抓取。

**更新配置寄存器**

头部字是命令链接抓取中读取的第一个字。随后的读包含要更新的配置寄存器的新值。寄存器值按接收顺序更新。

### 3.7 仲裁

当多个通道想要使用单个总线接口来发送传输时，就需要进行通道仲裁。

每个通道都有一个寄存器来设置该通道的优先级（CH\_CTRL.CHPRIO）。架构中定义的这个优先级寄存器连接到 AXI 上的 QoS 位，但它也会影响该通道所使用的仲裁方案。软件负责恰当地调整各通道的优先级，因为 DMA 单元并不知道哪个通道的操作比其他通道的时间更为关键。软件只能在通道被停止或处于 IDLE 时更改仲裁方案。仲裁方案很简单，以便软件灵活调整。

#### 3.7.1 仲裁请求

当出现以下条件时，通道可以生成仲裁请求。

读仲裁请求的条件：

- 通道 FSM 已连同所有控制信息准备好下一个要读取的地址。
- 数据 FIFO 有足够的空间来存储完整的读响应。

写仲裁请求的条件：

- 通道 FSM 已连同所有控制信息准备好下一个要写入的地址。
- 数据 FIFO 中有一个完整的写 burst 等待发出。

这意味着通道写只能在首先将一个完整的 burst 读入 FIFO 后才能开始。这避免了读和写之间的循环依赖，因为写不必等待任何传入的读数据。

#### 3.7.2 仲裁方案

本节描述最近最少授权（Least-Recently Granted，LRG）仲裁算法。

**LRG 仲裁算法**

BIU 实现了一个 LRG 仲裁算法，用于选择服务哪个 DMA 通道请求。LRG 算法的输入参数是由请求中的 AXI arqos 和 awqos 属性所指示的优先级设置。优先级由软件在配置寄存器中设置，且只能在通道处于 IDLE 时更改。

仲裁策略根据通道的优先级设置分为两层：

- 基于优先级的仲裁层，在不同优先级级别的通道之间进行仲裁。
- 轮询（round-robin）方案仲裁层，在具有相同优先级级别的通道之间进行仲裁，依据是它们中哪个最近最少被授权。

如果每个通道的优先级设置不同，则基础层是一个固定的仲裁方案。当多个请求具有不同的优先级时，具有最高优先级的单个请求赢得仲裁。当多个通道具有最高优先级时，采用轮询方案——最近最少授权（LRG），从而公平地共享总线接口。当所有通道都使用轮询方案时，只要它们有请求，每一轮所有通道都会被仲裁，因为仲裁在每个 burst 之后发生。当某个通道必须比其他通道具有更高优先级时，可以通过将其优先级值设置在其他通道之上，将其提升到固定优先级层。这可能导致低优先级请求被饿死（starvation），但它确保了高优先级任务的确定性执行。使用固定优先级方案的通道比轮询方案具有更高的优先级，因此它会首先被仲裁，直到其请求耗尽。此方案保持了软件在系统中设置任何优先级策略的灵活性。这也使得时间关键型任务得以发生，并使相同优先级的通道均等地共享总线。

轮询方案保存了已授权请求的历史。该方案按授权时间的降序对通道进行排序，即从最近最少授权到最近最多授权。当多个通道具有较高优先级时，轮询方案只考虑具有最高优先级级别的通道，并根据服务历史选择最近最少授权的通道。当较高优先级级别上的所有请求都已被服务、而这些相同的通道在拥有更多未完成请求的较低优先级级别上有了新请求时，同样适用此规则。也就是说，轮询方案会考虑所有具有相同（最高）优先级级别的通道，并选择最近最少授权的通道。

无限循环的命令链表可能导致较低优先级级别饥饿。

## 3.8 DMA 配置

DMAX 通过配置寄存器进行设置。这些寄存器分为若干帧，每帧占据 256 字节的地址空间。整个 DMA 单元占用 8kB 的配置地址空间。

> fig 5.26

#### 3.8.1 DMA 单元配置

以下四个寄存器帧与 DMA 单元相关：

- 安全配置寄存器帧 (DMASECCFG)：配置每个 DMA 通道的安全与特权属性，以及外部触发端口的安全属性。
- 安全控制寄存器帧 (DMASECCTRL)：包含影响所有配置为“安全”通道的状态和控制寄存器。
- 非安全控制寄存器帧 (DMANSECCTRL)：包含影响所有配置为“非安全”通道的状态和控制寄存器。
- 信息寄存器帧 (DMAINFO)：提供有关 DMA 单元能力和参数的信息。

#### 3.8.2 通道配置

每个 DMA 通道拥有独立的寄存器帧。配置寄存器仅在通道禁用时可写。当 CH(x)\_CMD 寄存器中的 ENABLECMD 位置位时，设置在整个命令执行期间被冻结。

配置命令的准则：

1. 寄存器字段必须仅包含允许的值（否则导致 REGVALERR）。
2. 设置必须描述一个有效的命令，即不存在冲突参数（否则导致 CFGCONFLERR）。

配置通道命令的步骤：

每个 DMA 通道都有自己的寄存器帧（register frame），其中包含通道专用的配置寄存器。配置寄存器仅在通道未使能时可写。当 CH<x>_CMD 寄存器中的 ENABLECMD 位被置位时，这些设置在命令执行的整个过程中被冻结。

要正确配置一个命令，写入配置寄存器的设置必须满足以下条件：

- 寄存器字段只能包含允许的值。要查看哪些值有效，参见"编程模型"。保留字段的所有位必须为零。不满足此条件将导致 REGVALERR。
- 这些设置必须描述一个有效的命令，即不存在冲突的参数。不满足此条件将导致 CFGCONFLERR。

**配置一个通道命令**

必须写入以下寄存器和字段来设置一个 DMA 命令：

1. CH<x>\_CTRL 寄存器：
   - CHPRIO —— DMA 通道优先级
   - TRANSIZE —— 数据传输的单位
   - XTYPE / YTYPE —— 预期数据传输的类型
   - USE\* 字段 —— 选择是否使用触发 / GPO / Stream 接口
   - DONETYPE / DONEPAUSEEN 字段 —— 控制在命令执行的哪个时间点发出 STAT\_DONE 标志，以及是否因此暂停通道。

2. 源/目标起始地址
   CH<x>\_SRCADDR 和 CH<x>\_SRCADDRHI 定义源起始地址，CH<x>\_DESADDR 和 CH<x>\_DESADDRHI 定义传输的目标起始地址。

3. 源/目标 size、Y-stride
   SRCXSIZE 和 SRCXSIZEHI 定义源 XSIZE，DESXSIZE 和 DESXSIZEHI 定义传输的目标 XSIZE 参数。这些字段位于 CH<x>\_XSIZE 和 CH<x>\_XSIZEHI 寄存器中。
   如果通过 YTYPE 选择了 2D 传输，则还必须通过 CH<x>\_YSIZE 寄存器中的 SRCYSIZE 和 DESYSIZE 字段设置 YSIZE 参数。此外，对于 2D 传输，还必须在 CH<x>_YADDRSTRIDE 寄存器中配置 SRCYADDRSTRIDE / DESYADDRSTRIDE 参数。

4. 源/目标地址递增：
   SRCXADDRINC 和 DESXADDRINC 在 CH<x>\_XADDRINC 寄存器中定义地址递增。
   这些字段编码为二进制补码数，因此也可以使用负值和零值。

5. CH<x>\_SRCTRANSCFG / CH<x>\_DESTRANSCFG 寄存器中的源/目标总线属性：
   - 安全和特权属性（\*NONSECATTR / \*PRIVATTR）
   - 内存和可共享性属性（\*MEMATTRLO / \*MEMATTRHI / \*SHAREATTR）
   - 最大 burst 长度（\*MAXBURSTLEN）

6. 如果 XTYPE 或 YTYPE 中所选的传输类型为 fill，则必须在 CH<x>\_FILLVAL 寄存器中设置填充值。

7. 对于模板化传输，必须在 CH<x>\_TMPLTCFG、CH<x>\_SRCTMPLT 和 CH<x>\_DESTMPLT 寄存器中设置模板模式和模板 size。要禁用模板化传输，将模板 size 设为零。

8. 如果使用触发（通过 USESRCTRIGIN、USEDESTRIGIN 或 USETRIGOUT 字段选择），则必须为已使能的触发配置触发参数。
   - 对于触发输入，必须在 CH<x>\_SRCTRIGINCFG / CH<x>\_DESTRIGINCFG 寄存器中设置以下字段：
     - \*TRIGINTYPE —— 输入触发的类型（仅软件、外部硬件或内部触发）
     - \*TRIGINMODE —— 触发输入模式（命令触发、DMAC 驱动的流控触发或外设驱动的流控触发）
     - \*TRIGINSEL —— 若选择了外部硬件类型，用于选择使用哪个外部触发端口；若选择了内部类型，用于选择连接到哪个通道。
     - \*TRIGINBLKSIZE —— 用于为流控触发模式定义触发块大小
   - 对于触发输出，必须在 CH<x>\_TRIGOUTCFG 寄存器中设置以下字段：
     - TRIGOUTTYPE —— 输出触发的类型（仅软件、外部硬件或内部触发）
     - TRIGOUTSEL —— 若选择了外部硬件类型，用于选择使用哪个外部触发端口（其他类型下无关紧要）

9. 如果要使用 GPO，则设置 GPO 值（CH<x>\_GPOVAL0）和使能掩码（CH<x>\_GPOEN0）。

10. 如果要使用 Stream 接口，则必须在 CH<x>\_STREAMINTCFG 寄存器中配置 STREAMTYPE 字段。

11. 要使能自动重启，必须设置重启计数器，或使能无限重启标志：
    - 将 CMDRESTARTCNT 设为预期循环次数减一，或
    - 将 CMDRESTARTINFEN 设为 1 以使能命令的无限自动重启。
    - 通过设置 CH<x>\_CTRL 寄存器中的 REGRELOADTYPE 字段，选择每个循环后要用其初始值重新加载的寄存器。

12. 对于命令链接，必须设置以下字段：
    - LINKADDREN 必须设为 1 以使能命令链接
    - LINKADDR / LINKADDRHI —— 用于设置链接命令描述符的地址
    - LINKMEMATTRLO / LINKMEMATTRHI / LINKSHAREATTR —— 用于设置抓取描述符时所使用的总线传输属性

如果某个特性未被命令使用，我们建议将与该特性相关的字段保留为复位值。

**空命令 (Empty Commands)**

存在这样一部分设置：它们描述了一个有效的命令，但其执行并不产生实际的数据传输。这类命令称为空命令，它们可能很有用。例如，用于发起一个链接命令链、设置 GPO 值，或使用触发特性与其他通道同步。

当 XTYPE 字段被显式设为 disable（3'b000），或者当 AXI5 接口既未配置数据读也未配置数据写时，就会执行一个空命令。

以下情况导致不通过 AXI5 接口进行数据读：

- 请求了显式空命令：

```
XTYPE = 'disable'
```

- 数据源配置为 AXI，但源 size 设为零：

```
( SRCXSIZE = 0 or (YTYPE != 'disable' and SRCYSIZE = 0) )
```

- 选择了 AXI 到 AXI 模式，但目标 size 设为零：

```
( DESXSIZE = 0 or (YTYPE != 'disable' and DESYSIZE = 0) )
```

以下情况导致不通过 AXI5 接口进行数据写：

- 请求了显式空命令：

```
XTYPE = 'disable'
```

- 数据目标配置为 AXI，但目标 size 设为零：

```
( DESXSIZE = 0 or (XTYPE != 'disable' and DESYSIZE = 0) )
```

- 选择了 AXI 到 AXI 模式，但没有数据生产者（源 size 设为零，且 2D 命令未选择 Y fill 模式，或 1D 命令未选择 X fill）：

```
( SRCXSIZE = 0 or (YTYPE != 'disable' and SRCYSIZE = 0) )
and
( ( YTYPE != 'disable' and YTYPE != 'fill' ) or ( YTYPE = 'disable' and XTYPE != 'fill' ) )
```

有意配置空命令的推荐方法是将 XTYPE 设为 disable。

**因无效设置导致的配置错误**

以下无效设置会导致配置错误。此时不进行任何数据传输，且 CH<x>\_ERRINFO 寄存器中的 CFGERR 和 REGVALERR 字段被置位。

- TRANSIZE 被设为大于总线宽度。
- 选择了不存在的触发资源：
  - 如果配置了硬件触发类型（SRCTRIGINTYPE、DESTRIGINTYPE 或 TRIGOUTTYPE = 2'b10），而 SRCTRIGINSEL、DESTRIGINSEL 或 TRIGOUTSEL 指向的硬件触发端口号过大。
  - 如果配置了内部触发类型（SRCTRIGINTYPE 或 DESTRIGINTYPE = 2'b11），而 SRCTRIGINSEL、DESTRIGINSEL 指向的通道号过大，或指向正在配置的通道自身。
  - 在 $product 没有硬件触发输入或触发输出端口时，配置了硬件触发类型（SRCTRIGINTYPE、DESTRIGINTYPE 或 TRIGOUTTYPE = 2'b10）。

**因冲突设置导致的配置错误**

以下设置会导致配置冲突错误。此时不进行任何数据传输，且 CH<x>\_ERRINFO 寄存器中的 CFGERR 和 CFGCONFLERR 字段被置位。

流控触发输入模式仅在 1D 源或目标下受支持。这意味着即使选择了 2D 传输类型，给定一侧的 YSIZE 也必须为 1。

- 2D 源下的源流控触发输入模式：

```
USESRCTRIGIN = 1'b1 and SRCTRIGINMODE = 2'b1X and XTYPE != 'disable' and YTYPE != 'disable' and SRCYSIZE > 1
```

- 2D 目标下的目标流控触发输入模式：

```
USEDESTRIGIN = 1'b1 and DESTRIGINMODE = 2'b1X and XTYPE != 'disable' and YTYPE != 'disable' and DESYSIZE > 1
```

- wrap 传输下的源流控触发输入模式：

```
USESRCTRIGIN = 1'b1 and SRCTRIGINMODE = 2'b1X and (XTYPE == 'wrap' or YTYPE == 'wrap')
```

流控触发模式意味着必须为给定方向配置数据传输。关于"未配置 AXI5 读或写"的定义，参见上文"空命令"一节。因此，以下设置是非法的：

- 无 AXI5 源数据时的源流控触发输入模式：

```
USESRCTRIGIN = 1'b1 and SRCTRIGINMODE = 2'b1X and No AXI5 read configured
```

- 无 AXI5 目标数据时的目标流控触发输入模式：

```
USEDESTRIGIN = 1'b1 and DESTRIGINMODE = 2'b1X and No AXI5 write configured
```

2D 传输类型下不允许模板化传输。

```
YTYPE != 'disable' and (SRCTMPLTSIZE != 0 or DESTMPLTSIZE != 0)
```

### 3.9 初始化

在设置各通道进行内存传输之前，必须先配置 DMA 控制器，为每个通道及其所附资源设置安全和特权属性。配置完成后，通道配置寄存器将受到保护，防止恶意访问。安全配置可以被锁定，直到 DMA 控制器 下次复位为止，以进一步保护安全设置。通道的特权设置可在通道处于 IDLE 时调整。当通道的安全或特权设置发生变化时，寄存器设置会被自动清除。

建议在更改安全或特权设置时，采用"写入并回读所需新状态"的序列，以确保更改成功。

### 3.10 中断操作

每个通道都有自己的中断，用于指示该通道内部的状态变化。还有一些 DMA 单元级别的中断，用于显示单元级别的状态变化。软件可以使能、禁用或清除这些中断。

当同时使用安全和非安全中断时，每个中断都有其运行在相应安全世界中的处理程序。这意味着在更改通道的安全状态时需要保持一致。当通道被配置为安全时，该通道的中断即被视为安全中断。
