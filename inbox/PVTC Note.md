## 1.2 概述

PVT 控制器可通过配置，使每个控制器下挂载多个嵌入式 TS（温度传感器）、VM（电压监测器）和 PD（工艺检测器）IP 模块实例。PVT 控制器提供通用读/写接口，便于客户在设计中接入不同类型的系统总线，例如 APB、IMGBUS、AXI-L 等。控制器还为每个 IP 实例配备了串行数据适配器，当嵌入式 IP 与 PVT 控制器的物理位置相距较远时，可大幅减少需要布线的信号数量。

## 4 功能特性

- 可配置 0 至 8 个嵌入式温度传感器 IP。
- 可配置 0 至 8 个嵌入式多通道（通常为 16 通道）电压监测器 IP。
- 可配置 0 至 24 个嵌入式工艺检测器 IP。
- 动态寄存器地址空间，由 PVT 控制器的编译（build）选项决定。
- 写锁定功能，防止意外的重新配置。
- 自动轮询电压监测器的各测量通道（通常为 16 通道）。
- 嵌入式 IP 采用星型拓扑串行连接，以最大限度减少信号布线。
- 内置时钟合成器，用于为嵌入式 IP 生成串行时钟和时序控制信号。
- 串行接口支持远端数据回环（loop-back），便于系统集成测试。
- 嵌入式 IP 可单独禁用（同时关闭其时钟门控）以节省功耗。
- 数据回收可采用中断驱动、轮询或纯粹基于告警事件的方式。
- 为便于代码开发，中断可被强制触发以用于测试。
- 提供采样丢弃功能，用于在过渡期间屏蔽已回收的数据。
- 每个 TS 与 PD 器件配备两路可编程（上升沿或下降沿触发）硬件告警，并带迟滞功能。
- 每个 VM 通道配备两路可编程（上升沿或下降沿触发）硬件告警，并带迟滞功能。
- 状态寄存器记录每个 TS、PD 及 VM 通道所接收数据的最小值与最大值。
- 每类 IP 各配备一个采样计数器，即 TS、VM、PD 器件共 3 个。
- 提供带中断请求（IRQ）的上电定时器，以支持 TS、PD 及 VM 器件的手动操作。
- 测试访问模式（Test Access Mode），可将控制器的串行测试访问数据寄存器接入 IJTAG（IEEE-1687）类型的嵌入式测试网络。

## 8 时钟方案

主时钟为总线接口时钟，用于驱动设计内部的大部分逻辑。PVT 控制器实际上采用单时钟域设计，其中总线接口时钟 `clk_sys` 作为主时钟。PVT 控制器内部的所有寄存器均在 `clk_sys` 的上升沿触发，并采用低电平有效的异步复位。

PVT 控制器还集成了三个时钟合成器，分别对应三类嵌入式 IP，即：

- TS
- VM
- PD

这些时钟合成器为从串行数据适配器（Slave Serial Data Adaptor）和嵌入式 IP 生成相应的时钟及定时选通信号，即：

- `clk_ts`
- `clk_vm`
- `clk_pd`

时钟合成器中的高电平/低电平计数器 `synth_hi` / `synth_lo` 对 `clk_sys` 进行整数分频，从而生成 `clk` 与 `*_clk_ip` 之间 **2:1 至 512:1** 的频率比。

此外，设计还使用独立的计数器生成与 `clk_ts`、`clk_vm` 和 `clk_pd` 对齐的定时控制选通信号（timing control strobes）。

这些定时选通信号由主串行适配器（Master Serial Adaptor）使用，用于控制：

- 串行数据输入的采样时刻；
- 串行数据输出的保持时间。

## 9 时序控制

主串行数据适配器（Master Serial Data Adaptor）的时序可以相对于合成时钟 `*_clk_ip` 的上升沿进行调整，从而以 `clk_sys` 的时钟周期为步长，调整：

- 串行数据输出的保持时间（hold time）；
- 串行数据输入的建立时间（setup time）。

当定时选通信号（timing strobe）的值设置为 `0` 时：

- 串行数据输出与 `*_clk_ip` 的上升沿对齐；
- 串行数据输入的采样时刻与 `*_clk_ip` 的上升沿重合。

在配置定时选通信号时，其数值**不得超过合成时钟周期**，即：

```text
synth_strobe <= (synth_hi + synth_lo + 1)
```

需要注意，从 PVT 控制器到 IP Wrapper 再返回 PVT 控制器的总往返延迟（round-trip time），对于以下路径：`[ts|vm|pd]_clk_ip`以及：`[ts|vm|pd]_sdo`其总延迟不得超过：`15 × clk_sys 周期`

## 复位方案

设计内部以及嵌入式 IP 中的所有寄存器均采用**低电平有效的异步复位方案**。

复位的置位（reset assertion）完全异步。为了避免复位释放时产生亚稳态，设计中采用**两级触发器同步电路（dual-flop meta re-time circuits）**，将内部复位的释放（reset de-assertion）同步到 `clk_sys` 的上升沿。

## 串行数据适配器

针对每一种嵌入式 IP Macro 类型，都配置了独立的 PVT Master，即：

- TS IP Macro 对应一个 PVT Master；
- VM IP Macro 对应一个 PVT Master；
- PD IP Macro 对应一个 PVT Master。

通常情况下，一个 Master 会向其所有处于激活状态的 PVT Slave 发送数据。但也可以禁止对一个或多个 Slave 进行配置，从而为不同的 Slave 应用不同的配置。例如，在配置多个电压监测器（Voltage Monitor）时，不同实例可能具有不同的通道轮询需求。

此外，还可以通过关闭某个 IP Macro 的时钟并强制其保持复位状态，完全禁用该 IP Macro，以支持节能。

PVT Master 的接收通路可以独立于发送通路运行。因此，当 PVT Slave 工作在自动模式下时，只要新的 IP Macro 数据可用，就可以自动更新 PVT 控制器内部的数据寄存器。

串行数据接口还提供环回（loop-back）功能，如图中红色路径所示，可在无需给嵌入式 IP Macro 上电的情况下进行系统集成测试。

## 11.2 SDA 读取

从 SDA Slave 寄存器读取数据时：

```text
sdif_wrn = 1'b0
```

SLV SDI 位流会被移位至 SLV SDO，期间延迟一个 `clk_ip` 周期。同时，寄存器读出的数据通过：

```text
sdif_rdata[23:0]
```

输出。

随后，该读取数据会被写入 PVT Controller 中对应的：

```text
[TS|PD|VM][n]_SDIF_RDATA
```

寄存器，其中 `n` 表示 IP 实例编号。

## 11.3 SDA 写入 / SDA 环回

当向 SDA 从设备寄存器写入数据时（`sdif_wrn = 1’b1`），SLV SDI 位流会自动移位到 SLV SDO（延迟一个 `clk_ip` 时钟周期，但除此之外不做任何修改），即：

```
sdif_rdata = sdif_wdata
```

随后，写数据的环回值可通过对应的 PVT Controller `[TS|PD|VM][n]SDIF_RDATA` 寄存器读取。

通过向（只读的）SDA `ip_data` 寄存器执行写操作，可以启用一种特殊的环回模式，即：

- `sdif_wrn = 1’b1`
- `sdif_addr[2:0] = 0x3`

在该模式下，环回数据值还会写入 PVT Controller 的 IP 数据寄存器，即 `[TS|PD][n]SDIF_DATA` 和 `VM[n]CH[m]SDIF_DATA`，其中 `m` 表示 VM 通道编号。

当向 TS/PD IP 数据寄存器写入环回数据时，SDA `ip_data` 中的 `ip_ch[3:0]` 字段必须设置为 `0x0`。

当向 VM IP 数据寄存器写入时，SDA `ip_data` 中的 `ip_ch[3:0]` 字段决定更新哪一个 VM 通道寄存器 `[m]`。

`[TS|PD|VM][n]SDIF_RDATA` 环回功能可用于验证 PVT Controller 与远端 PVT 从设备之间串行数据传输的完整性。

特殊的 `[TS|PD][n]SDIF_DATA` 和 `VM[n]CH[m]SDIF_DATA` 环回功能用于在无需给嵌入式 IP 宏上电的情况下测试 PVT Controller 的工作情况，例如测试故障（fault）或告警（alarm）行为等。

请注意，当 PVT 从设备配置为自动数据恢复模式时，环回功能会被禁用，即 PVT Slave 的 `ip_ctrl` 寄存器中 `ip_auto` 位被置位时。

## SDA 自动数据恢复

在自动数据恢复模式下，`SDIF_STATUS` 寄存器中的 `sdif_lock` 标志被置位，同时 SDA 接口变为只写接口，即所有 SDA 读请求都会被忽略。

在该模式下，每当有新的数据采样可用时，SLV 都会自动将 `ip_data[23:0]` 以数据流形式发送给 PVT Controller，同时设置：

- `sdif_addr[2:0] = 0x3`
- `sdif_wrn = 1’b1`

自动恢复得到的数据值可通过 PVT Controller 的以下寄存器获取：

```
[TS|PD|VM][n]SDIF_RDATA
```

以及：

```
[TS|PD][n]SDIF_DATA
VM[n]CH[m]SDIF_DATA
```

## 11.5 SDA SDIF 编程

通过 `[TS|VM|PD]_SDIF` 控制寄存器访问 SDA Slave。访问前需要配置：

- `sdif_wdata[23:0]`
- `sdif_add[2:0]`
- `sdif_wrn`

然后将 `sdif_prog` 位置位，以发起 SDA 读或写请求。

通常，一次 PVT 寄存器写操作即可完成上述 SDA 读写请求的配置。

串行数据按照已配置的 IP 时钟速率进行移位。每次 SDA 读或写访问大约需要：

```text
32 × (clk_sys 频率 / *_clk_ip 频率)
```

个 `clk_sys` 周期。

发起一次编程请求后，`*_SDIF_STATUS` 寄存器中的 `sdif_busy` 标志会被置位。在当前访问完成之前，任何新的读或写编程请求都会被忽略。

## 11.6 SDA Controller 工作模式

SDA Slave Controller 有两种工作模式：

- 手动模式（Manual，默认模式）
- 自动模式（Automatic）

在这两种模式下，嵌入式 IP Macro 都通过 `ip_cfg` 和 `ip_cfga` 寄存器进行配置。

### 手动模式

当 PVT Slave 的 `ip_ctrl` 寄存器中：

```text
ip_auto = 0
```

时，SDA Slave 工作在手动模式。

此时，嵌入式 IP Macro 直接由 `ip_ctrl` 寄存器中的以下字段控制：

- `ip_pd`
- `ip_rstn`
- `ip_run_once`
- `ip_run_cont`
- `ip_cload`

在手动模式下，用户需要自行保证 `PD`、`RSTN`、`CLOAD` 和 `RUN` 信号按照正确的顺序，并在正确的时间点施加。

一次转换完成后，嵌入式 IP 产生的采样数据会被捕获到 SDA Slave 的：

```text
ip_data
```

寄存器中。

用户需要通过以下两种方式之一获取采样数据：

1. 轮询 `ip_data` 寄存器，等待转换完成；
2. 在读取 `ip_data` 前预留足够的转换时间。

随后读取 `ip_data` 寄存器，即可从 Slave SDA 获取采样结果。

### 自动模式

当 PVT Slave 的 `ip_ctrl` 寄存器中：

```text
ip_auto = 1
```

时，SDA Slave 工作在自动模式。

在该模式下，嵌入式 IP Macro 由 Slave SDA 自动控制。

当 `ip_ctrl` 寄存器中的：

```text
run_once
```

或：

```text
run_cont
```

置位后，Slave SDA 会自动按照规定时序控制：

- `PD`
- `RSTN`
- `CLOAD`
- `RUN`

从而驱动嵌入式 IP 完成一次或多次转换。

每次转换结束后，嵌入式 IP 的采样数据首先被捕获到 SDA Slave 的：

```text
ip_data
```

寄存器中，随后再**自动串行回传至 PVT Controller**。

## 11.7 SDA VM 通道轮询

在自动模式下，SDA Slave Controller 对 `run_once` 和 `run_cont` 两种操作均支持 VM 通道轮询。

自动通道轮询的一般配置流程如下。

### 1. 使能 VM 自动模式

当 VM 工作在自动模式时，必须将 SDA Slave 的 `ip_ctrl` 寄存器中的：

```text
ip_vm_mode
```

位置位，以保证通道轮询功能正常工作。

### 2. 配置 VM SDA Slave 的默认参数

配置 VM SDA Slave 的：

```text
ip_cfg
```

寄存器默认值。

需要特别注意，VM 通道选择字段默认必须设置为：

```text
0x00
```

具体字段为：

```text
VM1 / VM2 : ip_cfg2[4:0]
VM3       : ip_cfg1[4:0]
```

### 3. 配置上电延迟

配置：

```text
ip_tmr
```

寄存器，用于设置 `V3` 上电延迟。

该延迟以 IP 的 `clk` 周期数为单位。

### 4. 配置通道轮询

配置：

```text
ip_polling
```

寄存器。

其中：

#### `vm_ch_ena[15:0]`

用于使能需要轮询的 VM 通道：

```text
bit[0]  = Vin0
bit[1]  = Vin1
...
bit[15] = Vin15
```

例如：

```text
vm_ch_ena[15:0] = 16'h0005
```

表示轮询：

```text
Vin0
Vin2
```

#### `vm_ch_sel[3:0]`

用于指定默认通道。

当：

```text
vm_ch_ena[15:0] = 16'h0000
```

或者 `vm_ch_req` 被置位时，会使用 `vm_ch_sel[3:0]` 指定的通道。

`vm_ch_req` 用于**临时中断正常的通道轮询序列**，请求立即测量由：

```text
vm_ch_sel[3:0]
```

指定的输入通道。

### 11.8.1 功能模式

在功能模式下，当嵌入式 IP 处于激活状态时，所配置的 `synth_hi` / `synth_lo` 数值必须生成一个串行时钟 `clk_*`，并确保其频率处于嵌入式 IP 的工作频率范围内。

PVTC 系统时钟 `clk_sys` 的频率通常由客户的系统需求决定。

随后需要配置 PVTC 时钟分频器，使 `clk_sys` 与 `*_clk_ip` 之间具有合适的分频比，从而为嵌入式 IP Macro 提供满足要求的工作频率。

例如：

| 项目               | 数值           |
| ------------------ | -------------- |
| 系统时钟频率       | 75.0 MHz       |
| 嵌入式 IP 工作频率 | 4 MHz ～ 8 MHz |

在这种情况下，将 `clk_sys` 与 `*_clk_ip` 的分频比设置为 `10:1`，则嵌入式 IP 的工作频率为 `75.0 MHz / 10 = 7.5 MHz`，该频率位于允许的 `4 MHz ～ 8 MHz` 工作范围内。

因此，Clock Synthesiser 的 `*_CLK_SYNTH` 寄存器中，`SYNTH_HI` 和 `SYNTH_LO` 字段均应配置为 `0x04`，从而获得总分频比为 `10`、占空比为 `50/50` 的串行时钟 `clk_*`。

`synth_strobe` 的配置值应能够覆盖最差情况下串行数据路径的传播延迟，同时不得超过合成时钟周期，即：

```
synth_strobe <= (synth_hi + synth_lo + 1)
```

在下图所示波形中，`synth_strobe` 配置为 `0x5`，以提供足够的建立时间裕量 `sdo_tSU`，确保 PVTS 的 SDO 能够在 PVTC 端（MST SDI）被可靠采样，即在 `clk_sys` 的 T5 上升沿进行采样。

PVTC 端 PVTS SDO 的建立时间裕量 `sdo_tSU` 可近似表示为：

```
sdo_tSU = synth_strobe / clk_sys - (clk_tP + sdo_tD + sdo_tP)
```

类似地，PVTS 端 PVTS SDI 的建立时间裕量 `sdi_tSU` 可近似表示为：

```
sdi_tSU = (((synth_hi + 1 + synth_lo + 1) / clk_sys) + clk_tP) - ((synth_strobe / clk_sys) + sdi_tP)
```

## 13 中断

该设计从 Controller 提供一个**高电平有效、等级触发（level-sensitive）**的硬件中断输出。

该中断输出由所有嵌入式 IP Macro 的中断源以及公共延时定时器（common delay timer）进行逻辑或（OR）后生成。

中断的使能、屏蔽和状态可通过 IRQ 控制寄存器进行管理，详细说明见第 16.4.2 节。

各个 IP 实例产生的中断会按照 IP 类型分别合并，每种 IP 类型形成一个中断，其状态可通过 `IRQ_[TS|VM|PD]_STATUS` 寄存器查看。寄存器中某位置位时，该位的索引号表示产生中断条件的 IP 实例编号。

每个 IP 可以基于以下中断源产生中断：

- `*_irq_smpl`：表示对应 IP 实例的采样数据已更新。
- `*_irq_alarma`：表示获取到的采样值已超过对应 IP 实例所配置的 Alarm A 阈值；对于 VM，则表示对应 VM 通道的采样值超过 Alarm A 阈值。
- `*_irq_alarmb`：表示获取到的采样值已超过对应 IP 实例所配置的 Alarm B 阈值；对于 VM，则表示对应 VM 通道的采样值超过 Alarm B 阈值。
- `*_irq_fault`：表示对应 IP 实例已报告故障。

当中断事件发生时，设计会检测其上升沿，并在对应的中断源寄存器 `*_IRQ_SRC` 中置位相应标志。

`*_IRQ_SRC` 中的各个位分别与 `*_IRQ_ENA` 寄存器中对应的中断使能位进行逻辑与（AND），从而生成中断请求位。

这些 IRQ 位随后进行逻辑或（OR），并由 `clk` 寄存后生成 IRQ 控制寄存器对应的中断输出。

一旦置位，中断源位会保持置位状态（sticky），必须向对应的 `[TS|PD|VM][n]_IRQ_CLR` 寄存器或 `VM[n]_IRQ_ALARM[A|B]_CLR` 寄存器相应位写入 `1` 才能清除。

如果对应 IRQ 已使能，清除中断源位时也会同时清除相应的 IRQ。

当以下标志置位，或者向 `*_IRQ_TEST` 寄存器中的强制中断位写入 `1` 时，会触发中断事件。强制中断功能可用于软件测试，以手动产生中断。

- `smpl`
	每当获取到新的 IP 数据样本时置位。
- `alarma`
	每当达到 Alarm A 阈值时置位。
- `alarmb`
	每当达到 Alarm B 阈值时置位。
- `fault`
	每当 IP 将其故障输出置位时置位。

## 13.1 中断使用建议

通常情况下，嵌入式温度传感器和电压监测器会持续运行，并依靠 Alarm 中断来指示测量值超出允许范围的情况。

对于这类 IP，用户通常会关闭 Sample Done 中断，除非需要记录每一次采样数据。

如果同一类型的所有 IP 都同时使能，则这些嵌入式 IP Macro 会同步运行，并在每个转换周期的同一个时钟边沿置位各自的 Sample Done 标志。

有关中断使能及中断服务处理的指导，详见第 18.2 节和第 18.5 节。



## 14 告警

该设计为每个嵌入式 IP Macro 提供两个告警：Alarm A 和 Alarm B。

每个告警均支持可编程迟滞（hysteresis），并可配置为检测采样值越过上升阈值或下降阈值的情况。

当迟滞阈值与告警阈值设置为相同值时，告警功能被禁用，默认配置即为此状态。

告警使能后，当回传的采样值达到或越过所配置的上升或下降告警阈值时，将产生中断。

告警触发后，迟滞阈值用于形成一个**恢复区间**。只有采样值越过迟滞阈值、重新满足告警触发前置条件后，该告警才能再次触发，从而避免采样值在告警阈值附近波动时反复产生告警。

## 14.1 下降告警

当**迟滞阈值高于告警阈值**时，该告警被配置为下降告警（Falling Alarm）。

对于下降告警，当回传的采样值满足：

```
sample >= hysteresis threshold
```

时，告警进入**待触发状态**。

之后，当采样值下降并满足：

```
sample <= alarm threshold
```

时，告警触发。

告警触发后会自动退出待触发状态。在采样值再次满足：

```
sample >= hysteresis threshold
```

之前，该告警不会再次触发。

如果收到无效的采样数据，例如检测到非预期的 `fault` 或 `type` 标志，告警同样会退出待触发状态。

这里的逻辑实际上可以概括为：

`采样值 ≥ 迟滞阈值` → **允许下一次告警触发**

`采样值 ≤ 告警阈值` → **触发下降告警**

## 14.2 上升告警

当迟滞阈值设置为**低于告警阈值**时，即构成上升告警（Rising Alarm）。

配置为上升告警后，在以下任一情况下，告警会进入**可触发状态**：

a. 对应的时钟合成器（TS、VM 或 PD）首次使能时，即进行初始转换时；
b. 获取到的采样值小于或等于迟滞阈值时；
c. 收到无效采样值时，例如检测到非预期的 `fault` 或 `type` 标志。

告警进入可触发状态后，当获取到的采样值满足：

```
sample >= alarm threshold
```

时，上升告警触发。

告警触发后会自动退出可触发状态，并且只有当采样值再次满足：

```
sample <= hysteresis threshold
```

时，告警才会重新进入可触发状态。

## 15 测试支持

该系统在设计上同时支持数字逻辑的量产测试（Production Test）和功能测试（Functional Test），但系统整体测试方案需要由客户自行定义。

### 15.1 量产测试

PVT Controller 以 RTL 形式交付，其中不包含专用的 SCAN 逻辑。如果实际实现需要 SCAN 测试，则应由客户在物理实现流程中插入相应的扫描单元。

嵌入式 IP Macro 可能已经集成专门设计的 SCAN Chain，用于量产测试。控制该扫描链所需的信号均引出至顶层，因此在需要时，可以对该扫描链进行独立测试。

高电平有效的测试模式使能输入 `tm_te` 用于使 PVT Controller 和嵌入式 IP 进入 SCAN 测试模式。

当 `tm_te` 置位时：

- 设计中的所有时钟，包括合成的 IP 时钟，均由外部 `clk` 输入直接驱动；
- 设计中的所有复位，包括 IP 复位，均由外部 `rstn` 输入直接驱动；
- 嵌入式 IP 中模拟核心的输出会被置于已知状态。

嵌入式 IP 中的 SCAN Chain 包含多个寄存器。当 `scan_en` 置位时，这些寄存器组成一个移位寄存器链。

在 `scan_en` 置位的情况下，施加 `clk` 时钟后，数据会从 `scan_in` 串行移入，并沿扫描链逐级移位，最终从 `scan_out` 输出。

典型的测试流程如下：

1. 置位 `tm_te`，进入 SCAN 测试模式。
2. 置位 `scan_en`，通过 `scan_in` 串行移入数据，建立所需的扫描测试向量。
3. 清零 `scan_en`，施加一个 `clk` 时钟，使目标触发器捕获组合逻辑的测试结果。
4. 再次置位 `scan_en`，通过 `scan_out` 将捕获结果串行移出，以判断组合逻辑测试是否通过。

### 15.2 测试访问模式（TAM）

PVT Controller 提供一个专用接口，用于访问一组串行测试数据寄存器（Test Data Register，TDR）。

这些 TDR 设计用于组成 JTAG 或 IJTAG（IEEE 1687）嵌入式测试网络的一部分。

图 19 展示了 TDR 的配置方式及其与 PVT Controller 测试访问接口之间的连接关系。

如果客户的实现不需要该附加功能，可以通过编译时宏从设计中移除 TAM，具体参见第 12.3 节。

通过 STA 端口，可以利用 TDR 寄存器：

- 配置和控制 PVT Controller 的部分内部功能；
- 获取远端 Monitor IP Block 的数据。

当 PVT Controller 的 STA 端口处于激活状态时：

- APB 接口被禁用；
- 中断功能被禁用；
- 告警功能被禁用；
- 中断和告警均不会向系统输出。

处于 TAM 模式时，对 Controller 的访问仍会正常完成，不会造成接口锁死。其中：

- 读操作返回固定十六进制值 `0xdeadc0de`；
- 写操作会被忽略。

退出 TAM 模式后：

- 串行时钟合成器被禁用；
- 通过串行接口连接的 IP 被禁用；
- `PVT_TAM_STATUS` 寄存器会被更新，详见第 16.4.1.2.7 节。

在 TAM 模式下，建议使用 **Run Once** 模式从 IP Block 获取采样数据。

虽然也可以将这些 IP 配置为 **Run Continuous** 连续运行模式，但不建议这样做，因为通过 IJTAG 网络读取数据时可能发生采样数据丢失。

进入 TAM 模式以及通过 TAM 访问 PVT Controller 寄存器，**不会受到硬件锁和软件锁功能的限制**。

如果需要禁止对 TDR 的访问，应根据实际需求在 JTAG Test Access Port Controller 中实现相应的访问控制。

## 15.2.1 测试访问模式接口

PVT Controller 通过置位 TDR-0 中的 `ta_req` 位进入 TAM。

当 `ta_req` 置位后，PVT Controller 会关闭串行 Slave 接口及其对应的时钟合成模块。完成这些模块的关闭后，PVT Controller 会向外部接口置位 `ta_ack` 信号。关闭过程所需的时钟周期数取决于当时时钟合成器的状态。

在整个 TAM 访问期间，`ta_req` 必须始终保持置位。

在 PVT Controller 内部，当 `ta_ack` 置位后，MR75007 的工作时钟会由 `apb_clk` 切换为测试时钟 `tck`。该时钟切换采用无毛刺方式，并在两个时钟均处于低电平阶段时完成。

退出 TAM 时，需要清零 TDR-0 中的 `ta_req` 位。

`ta_req` 清零后，PVT Controller 会再次关闭串行 Slave 接口及其对应的时钟合成模块。关闭完成后，PVT Controller 会清零 `ta_ack`。

在 PVT Controller 内部，当 `ta_ack` 清零后，MR75007 的工作时钟会由 `tck` 切换回 `apb_clk`。

在 TAM 模式下，PVT Controller 的所有告警和中断均被禁用。在 TAM 期间发生的任何告警或故障条件都不会发送至系统，同时采样计数器也不会在该模式下更新。

### 注意事项

1. 在 PVT Controller 内部，在完成时钟切换之前，TDR 与 MR75007 之间的信号均按异步输入处理。为了确保可靠进入 TAM，来自 TDR-0 的 `ta_req` 位在使用前会先同步到 `clk_sys` 时钟域。
2. 内部 `ta_ack` 信号由 `clk_sys` 时钟驱动。在用于启动时钟切换之前，该信号会先同步回 `tck` 时钟域。
3. 为保证时钟切换机制正常工作，测试时钟 `tck` 的频率必须明显低于 `clk_sys`。
4. TDR 内部寄存器同时使用测试时钟的上升沿和下降沿，因此可用于满足建立时间的时间窗口只有 `tck` 的半个周期。
5. 为保证 Monitor 在退出 TAM 后能够正常工作，退出 TAM 时会关闭连接到 Monitor 的串行接口及其对应的时钟合成模块。
6. 如果设计不需要 TAM，则所有与 TAM 相关的输入都必须连接到逻辑 `0`，以保证 PVT Controller 在正常工作模式下功能正确。

## 15.2.4 TDR 时序细节

### 15.2.4.1 TDR 数据移入/移出

要将数据移入 TDR 或从 TDR 移出，需要在 `T0` 时刻 `tck` 的下降沿将 `tdr_shift` 以及对应 TDR 的 `tdr_sel` 置为 `1`。

当 `tdr_shift` 和 `tdr_sel` 保持有效时，`tdr_sin` 的值会在每个 `tck` 上升沿被采样。

所选 TDR 的 `tdr_sout` 数据在 `tck` 的下降沿输出，其中 `Sout-0` 在 `T0` 的下降沿有效，后续各位依次在之后的下降沿输出。

当所需位数全部移入 TDR 后，在 `Tn` 时刻 `tck` 的下降沿将 `tdr_shift` 清零。此后，可将已经移入的数据更新到 TDR 中。

### 15.2.4.2 TDR 数据更新/捕获

要更新 TDR 的内容，需要在 `T0` 时刻 `tck` 的下降沿将 `tdr_update` 和对应 TDR 的 `tdr_sel` 置位。

此前在 `tdr_shift` 阶段移入 TDR 的数据，会在 `T1` 时刻 `tck` 的上升沿被锁存到内部寄存器中。

要将 PVT-C TAM 输出的数据捕获到 TDR 中，需要在 `T0` 时刻 `tck` 的下降沿将 `tdr_capture` 和对应 TDR 的 `tdr_sel` 置位。

数据会在 `T1` 时刻 `tck` 的下降沿被捕获。之后可通过 `tdr_shift` 操作将捕获的数据从 TDR 中串行移出。

## 15.2.5 TAM 读取 IP Monitor 的操作流程

在 TAM 模式下访问单个 Monitor 时，需要按照图 23 所示的流程进行操作。

该流程适用于所有已连接的 Monitor 类型。针对不同系列的 Monitor，只需要对发送给 Monitor 的数据字进行少量调整。

### 单个 TAM IP Block 读取注意事项

1. 进入 TAM 后，连接到串行 Slave 的串行接口会被禁用，同时 Slave 保持在复位状态。

	此步骤用于选择后续需要使能和访问的串行接口及对应 Monitor。

	向 `[TS|VM|PD]_SDIF_DISABLE` 寄存器写入数据，清除需要访问实例对应的 Disable 位。

	各位域功能详见第 16.4.3.2.2 节。

2. 进入 TAM 后，时钟合成器会被清零并禁用。

	此步骤需要根据 TAM 模式下所使用的 `tck` 频率，为时钟合成器配置合适的分频参数。

	各位域功能详见第 16.4.3.2.1 节。

3. 在串行编程过程中，`tck` 必须持续运行，以确保数据能够正确移入远端串行 Slave。

	可以通过轮询 TDR-3 中的 `ta_lock` 和 `ta_busy` 位检查操作是否完成。

	另一种方法是先提供固定数量的 `tck` 周期，再检查 `ta_lock` 和 `ta_busy` 的状态。这样可以避免为了轮询状态而进行大量耗时的 TDR 移入、移出操作。

4. 通过写入 `SDA_IP_CTRL` 寄存器触发转换后，必须继续提供 `tck`，以确保串行接口以及所连接 IP 能够正常工作。

	IP 上电、完成测量以及通过串行接口返回结果所需的时钟周期数，取决于：

	- 所连接的 IP 类型；
	- 时钟合成器中配置的分频比。

	完成上述操作所需的最小时钟周期数，请参考对应 IP 的数据手册。

5. 如表 7 所示，bit `[18]` 为 `done` 位。

	只有当系统从串行 Slave 接收到一个有效数据字后，`done` 位才会置位。

	可以持续轮询 `done`，直到读取到有效数据。

	也可以采用前述固定时钟周期计数的方法，即先提供足够数量的 `tck` 周期，再检查 `done` 状态。这样同样可以减少为了确认有效数据是否到达而执行的 TDR 移入、移出次数。

6. 在执行下一次转换之前，应对 `ta_clear` 位进行一次置位再清零操作，置位时间至少保持 `1` 个 `tck` 周期。

	该操作会清除 `done` 状态，以便在后续采样中重新判断新的 `done` 状态。

7. 退出 TAM 时，时钟合成器会被清零并禁用，同时恢复告警和中断功能。
